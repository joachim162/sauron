# Apache Reverse Proxy OIDC Authentication
#security #authentication #oidc #apache #proxy #docker

Sauron's REST API supports OpenID Connect (OIDC) authentication via an Apache reverse proxy running `mod_auth_openidc`. The proxy terminates TLS, handles the OIDC authorization code flow, and passes the authenticated user's identity to the API via a trusted header.

## Architecture

```
Browser ──HTTPS──► Apache (mod_auth_openidc)
                       │
                       ├─ OIDC flow ──► Authentik (IdP)
                       │
                       └─ Sets X-Remote-User: user@example.com
                              │
                              └──► Sauron API (localhost:3000)
                                   Verifies trusted IP + looks up user
```

**Key principle:** The API trusts the `X-Remote-User` header only from known proxy IPs. Clients must never be able to reach the API directly — it binds to `localhost:3000` and is only accessible through the Docker network.

## OIDC Flow

1. **Unauthenticated request** to `https://host/api/v1/servers`
2. Apache's `mod_auth_openidc` returns **302** redirect to Authentik's `/authorize` endpoint
3. User authenticates at Authentik (login page, MFA, etc.)
4. Authentik redirects back to `https://host/callback?code=...&state=...`
5. `mod_auth_openidc` **exchanges the code** for tokens, validates them, extracts the `email` claim
6. Apache **sets `X-Remote-User`** header to the email and **proxies** the original request to the API
7. Sauron API's `ProxyAuth` handler verifies the source IP is trusted, looks up the user by email, and authorizes the request

## Docker Setup

Defined in `docker-compose.yml` with three services:

| Service | Image | Purpose |
|---------|-------|---------|
| `apache` | Custom (`httpd:2.4-bookworm` + `mod_auth_openidc`) | TLS termination + OIDC + reverse proxy |
| `sauron_api` | Custom | Sauron REST API (Mojolicious) |
| `postgres` | `postgres:15` | Database backend |

The API **does not expose port 3000 externally** — only Apache's ports 80/443 are published.

## Apache Configuration

Generated at container startup by `apache/docker-entrypoint.sh` from environment variables.

### Key Directives

```apache
# OIDC settings (from env vars)
OIDCProviderMetadataURL https://authentik.example.com/application/o/app/.well-known/openid-configuration
OIDCClientID <from OIDC_CLIENT_ID>
OIDCClientSecret <from OIDC_CLIENT_SECRET>
OIDCRedirectURI https://host/callback
OIDCScope "openid profile email"
OIDCRemoteUserClaim email

# Protected paths — require OIDC auth
<Location /api/v1>
    AuthType openid-connect
    Require valid-user
    RequestHeader unset X-Remote-User
    RequestHeader set X-Remote-User "%{OIDC_CLAIM_EMAIL}e"
    ProxyPass http://sauron_api:3000/api/v1
    ProxyPassReverse http://sauron_api:3000/api/v1
</Location>

# Callback — mod_auth_openidc handles code exchange
<Location /callback>
    AuthType openid-connect
    Require valid-user
</Location>

# Public paths — no OIDC, API handles its own auth
<Location /auth/login>
    ProxyPass http://sauron_api:3000/auth/login
    ProxyPassReverse http://sauron_api:3000/auth/login
</Location>
```

### Critical Detail: `RequestHeader unset X-Remote-User`

This directive **strips any client-supplied `X-Remote-User`** before setting it from the OIDC claim. Without it, an attacker could inject the header directly. Apache only sets it **after** successful OIDC authentication.

### SSL/TLS

Self-signed certificates for development are generated by `apache/tls/generate-dev-cert.sh`. The `Listen 443` directive is required in the config (not included in the default `httpd.conf`).

## API-Side Handling

### ProxyAuth Security Handler (`SauronAPI.pm`)

The `ProxyAuth` handler in the OpenAPI security configuration:

1. Reads the trusted IP list from config (`proxy_auth.trusted_ips`) or `PROXY_AUTH_TRUSTED_IPS` env var
2. Checks the request's remote address against trusted IPs (supports CIDR notation via [[NetAddr-IP-Syntax-Fix|`Net::Netmask`]])
3. Reads `X-Remote-User` header
4. Looks up the user by email (or username, depending on `proxy_auth.match` config)
5. Stashes user context for controllers

### Proxy Login Endpoint (`Auth.pm:proxy_login`)

`GET /auth/proxy-login` is a dedicated endpoint for proxy-authenticated requests. It uses the same trusted-IP logic but returns user info directly (no OpenAPI validation).

### Me Endpoint (`Auth.pm:me`)

`GET /auth/me` checks proxy auth header first (if from trusted IP), then falls back to `bff_session` cookie. This lets the frontend detect both auth states.

## Configuration

### Docker Compose Environment

```yaml
apache:
  environment:
    OIDC_ISSUER: "https://authentik.example.com/application/o/app/"
    OIDC_CLIENT_ID: "${OIDC_CLIENT_ID}"
    OIDC_CLIENT_SECRET: "${OIDC_CLIENT_SECRET}"
    OIDC_CRYPTO_PASSPHRASE: "${OIDC_CRYPTO_PASSPHRASE}"
  env_file:
    - .env

sauron_api:
  environment:
    PROXY_AUTH_TRUSTED_IPS: "127.0.0.1,::1,172.0.0.0/8"
```

### API Config (`sauron_a_p_i.yml`)

```yaml
proxy_auth:
  header: X-Remote-User
  match: email
  trusted_ips:
    - 127.0.0.1
    - ::1
```

The `PROXY_AUTH_TRUSTED_IPS` env var overrides the config file values. In Docker, set it to the network range of the Apache container.

## Coexistence with Other Auth Methods

The API supports three authentication methods that work simultaneously:

1. **BearerAuth** — Personal Access Tokens (`Authorization: Bearer <pat>`)
2. **CookieAuth** — Browser session cookies (`bff_session`)
3. **ProxyAuth** — Trusted reverse proxy header (`X-Remote-User`)

Each OpenAPI endpoint can require one or more of these via security definitions. The [[Browser-Session-Cookie-Auth-Flow|session cookie flow]] is unaffected by the proxy setup — `/auth/login` and `/auth/logout` are public paths proxied without OIDC.

## Common Pitfalls

- **Missing `Listen 443`**: The default `httpd.conf` does not include `Listen 443`. Without it, Apache accepts connections on 443 but cannot complete the TLS handshake.
- **Trailing slash in OIDC_ISSUER**: If the issuer URL has a trailing `/`, the `/.well-known/openid-configuration` path will have `//`, which some providers reject. The entrypoint script strips the trailing slash.
- **OIDCRedirectURI must match**: The redirect URI in Apache must exactly match one of the redirect URIs registered in the IdP's client configuration.
- **Docker network trusted IPs**: `PROXY_AUTH_TRUSTED_IPS` must include the Apache container's IP range, not just `127.0.0.1`.
